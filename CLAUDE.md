# CLAUDE.md - Project Conventions and Guidelines

## Project Overview
SheetPredict — an AI-guided platform that helps non-expert analysts build, explore, and deploy ML models without writing code.

**One product name, SheetPredict (#765).** Pages show `COMPANY.serviceName` (`apps/frontend/lib/legal/company.ts`); `COMPANY.valueLine` equals `docs/product/positioning.md` (sign-up page test). API vendor media type: `application/vnd.sheetpredict.v1+json`. `apps/backend/tests/test_security/test_product_name.py` fails on a retired name in any tracked text file, comments and guides included — describe an old name without writing it. Identifiers keep theirs (repo, packages, databases, buckets, test-user address). The only exempt file is `positioning.md`.

> This file holds durable conventions: the rule, where it lives, and the guard that enforces it. `#NNN` points at the PR with the story; per-issue history lives in git, not here.

## Architecture

### Frontend (`apps/frontend/`, Next.js)
- App Router, TypeScript strict, Tailwind CSS.
- **Auth (#527, #844):** NextAuth v5 (Google, GitHub). The session callback mints an HS256 JWT (`sub=userId`, `iat`, `exp`; `lib/api-token.ts`). **`session.apiToken` is the only credential that may reach the backend** — provider tokens are not persisted, and a proxy route with no `apiToken` answers 401, never a placeholder (`__tests__/lib/noProviderTokenForwarding.test.ts`). Backend verifies with PyJWT (`nextauth_auth._verify`: HS256 only, `exp` + non-empty `sub` required, 30s leeway); user path catches `jwt.PyJWTError`, admin path maps every failure to 404. Backend tests mint via `tests/api_tokens.py::mint_api_token` (hand-built with `hmac`, independent of the verifier).
- **Tailwind v4, CSS-first (#345):** no `tailwind.config.*`; the theme is `app/globals.css` (`@theme`, `@utility`, `@custom-variant dark`, `@plugin` — the only way a plugin loads). Tokens are `oklch`: never wrap one in `hsl(var(--x))` (invalid CSS, dropped silently). Every semantic token needs a `-foreground` pair in both `:root` and `.dark`. Guard: `__tests__/styles/themeTokens.test.ts` (real PostCSS).
- **Dark mode (#407):** `next-themes` with `attribute="class"` — must stay, `@custom-variant dark` keys on it. Use semantic tokens (`bg-card`, `text-foreground`, `text-muted-foreground`, `bg-muted`, `border-border`), never `bg-white`/`text-gray-*`/`bg-gray-*` (`__tests__/styles/semanticColours.test.ts`; exemption `components/Sidebar.tsx`). `jest.setup.js` polyfills `matchMedia`.
- **Public pages (#473, #475):** `middleware.ts` is deny-by-default. Public prefixes: `/auth/`, `/legal/` (trailing slash kept so `/legality` stays protected) and `/api/` (self-guards with 401). Marketing pages are listed by **exact path** in `PUBLIC_PATHS` (`/pricing`), never as a prefix. **Anything under `/legal/` is public by construction** — never put a tool there; `/legal/terms` and `/legal/privacy` must stay anonymous. Legal identity, jurisdiction, refund window, backup window and sub-processors live in `lib/legal/company.ts`; each sub-processor row must trace to code that sends the data (e.g. `dataset_summarization.py` sends ≤5 sample rows to OpenAI), and retention wording is never stronger than the erasure cascade performs. `/pricing` renders `lib/billing/plans.json`, the one source of published prices/limits; `test_pricing_source_matches_plans.py` holds it equal to `plans.py` and ADR-003 — change all three together. ENTERPRISE is always "contact us".
- **`/admin` is authorised (#477, #613, #768):** `middleware.ts` rewrites `/admin*` to not-found unless the token email is in `ADMIN_EMAILS` (`lib/admin-allowlist.ts`). It **fails closed** (unset = nobody) and is the only admin concept (no role field). `session.isAdmin` only hides the sidebar link; never decide a route from it client-side. Backend mirror: `app/config.py::is_admin_email` + `require_admin` (404 for everyone else) — `GET /metrics` and every admin route use it. Guard: `e2e/workflows/admin-guard.spec.ts` (`@smoke`, `TEST_ADMIN_EMAIL`). Manual check on `next build && next start`: mint a cookie with `@auth/core/jwt` `encode` (salt `authjs.session-token`); `curl -w '%{http_code}' /admin` must print 404 for a non-listed email.
- **Middleware cookie (#469):** HTTPS writes `__Secure-authjs.session-token`, http the bare name; `getToken` defaults to bare. `middleware.ts` reads whichever is present (secure first) via `secureCookie`, never by detecting HTTPS (unreliable behind nginx). Never add a raw-header `${name}=` presence check (misses chunked `.0`/`.1` cookies). Guard: `__tests__/middlewareSecureCookie.test.ts` (real `getToken`; ESM deps whitelisted in `jest.config.js` `transformIgnorePatterns`). Accepted tradeoff: a bare cookie is accepted over HTTPS; JWT verification is the backstop.
- **Signup mode (#768, #780):** `SIGNUP_MODE=invite|open`, resolved identically by `lib/invite-allowlist.ts::resolveSignupMode` and `app/config.py::resolve_signup_mode`. Explicit value wins; unset in production = `invite`; unset in dev/test = open unless an allowlist is set; a typo fails closed; invite + empty list admits nobody; the credentials provider passes only in open mode. Compose requires `${SIGNUP_MODE:?}`; `preflight_staging_env.sh` refuses an invalid mode and `invite` with an empty `INVITE_ALLOWLIST`. Do not flip to `open` before the #768 backstops and #769 telemetry are live in production.
- **Erasure UI (#482, #743):** `/settings` → "Delete my account data" (`POST /users/me/erase`); dashboard rows → per-dataset erase (`POST /datasets/{id}/erase`). Only via `lib/services/erasure.ts` + `components/settings/ErasureConfirmDialog.tsx` (type-to-confirm). A manifest with `failures`/`completed_with_residuals` is an error to retry, never success (`hasResiduals`, `lib/types/erasure.ts`). "What is retained" copy tracks `erase_user` (billing is kept). Smoke erases a whole account only as the isolated `erasure` user.
- **Every `page.tsx` is reachable from navigation (#528):** `__tests__/navigation/routeReachability.test.ts` recognises `href`/`push`/`replace`/`redirect`/`route:` literals, workflow-stage `route:` entries (`lib/types/workflow.ts`), and framework roots (`/` + NextAuth pages derived from `auth.ts` `pages:`). It checks "referenced once", not a graph walk. Exceptions go in `KNOWN_ORPHANS` with reason + issue (self-cleaning); current: `/recipes`, `/datasets/[id]/engineer` (#738).
- **Large pages are shells over a component folder.** The CRAP gate attributes every JSX line in a page to the page component, so a new page line usually means splitting. dashboard → `components/dashboard/` (`StageOverview`, `RecentLists`, `lib/hooks/useOnboardingRedirect.ts`; sidebar entries are module-level `MENU_ITEMS` in `components/Sidebar.tsx`); predict → `components/predict/` (#838); upload → `components/upload/` (`useUploadFlow`, `uploadFlow.ts::toPreviewData`, #1054); model → `components/model-training/` (`useTrainingRun`, `ExcludedColumnsPanel`, #841); onboarding → `components/onboarding/`.
- **Stage pages and contracts (#919, #969):** a dataset's columns come from `GET /user_data/{id}` `columns` (fallback `data_schema[].field_name`), then `GET /datasets/{id}` — later stages receive a `UserData` id, which `/datasets/{id}` 404s (`lib/services/datasetColumns.ts::loadColumns`). `/features` records `{selectedFeatures, excludedFeatures}` (`lib/features/columnChoice.ts`); `useTrainingRun` sends the excluded half as `feature_config.exclude_columns` (never the target), which the backend reports as `excluded_user_columns`. `retrainKeeping` reruns with `feature_config.keep_columns`. **Each stage page has one e2e spec that mocks none of its routes** (`features-stage.spec.ts`, `train-form.spec.ts` `@smoke`). Request bodies are pinned to backend schemas through captured fixtures (`UPDATE_FIXTURES=1`): `test_train_request_schema_fixture.py` → `trainRequest.contract.test.ts`; the upload page renders captured `secureUploadHighRiskPii.json` (`test_secure_upload_pii_fixture.py`), whose `PIIReport` shape (`lib/types/api.ts`) is `PIIDetector.generate_pii_report`'s.
- **Predictions (#838):** `PredictionResult` renders per-record `input_warnings` (`{column: "unseen" | "missing"}`). The single form cannot send unseen/blank values, so the batch summary's `input_warning_count` is where UI users meet them.
- **Errors go through `lib/services/apiError.ts` (#767):** `throw await apiError(response, '<fallback>')` keeps the message and adds `status`/`detail`. A `quota_exceeded` body becomes `QuotaExceededError` and goes to the `planLimit` store (`lib/billing/planLimit.ts`), rendered by the one `components/billing/PlanLimitDialog` in the root layout — a new metered call adopts it just by using the helper. Retry loops never retry `QuotaExceededError`. `/api/chat` passes a backend 402 body through unchanged (other failures stay sanitised). `QUOTA_DETAIL_FIELDS` mirrors `enforcement.py::reserve` (`test_quota_enforcement.py::TestQuotaBodyMatchesTheFrontendParser`). `UsageWarningBanner` warns at ≥80% of a finite metric. `/settings/billing` reads `?checkout=…` once, then polls `/billing/status` (`CHECKOUT_POLL_MS × CHECKOUT_POLL_MAX`) until the tier moves. The real-402 e2e (`plan-limit.spec.ts`) runs as the PRO admin tenant with `PLAN_PRO_UPLOADS=2`; no other spec uploads as the admin tenant.
- **Glued text (#473, #603):** write `{' '}` after any `{expr}` followed by prose — the server render can drop the space and jsdom can't see it. `e2e/workflows/glued-text.spec.ts` checks served HTML (`e2e/helpers/gluedText.ts`). By hand: `curl <page> | grep -E '[A-Za-z0-9.,)]<!-- -->[A-Za-z0-9(]'`.
- **Layout follows the container (#809):** the shell reserves 256px left + 320px right (`lg:ml-64 lg:mr-80`), so viewport breakpoints fire too early inside a page. Use container queries (`@container` + `@3xl:`; `@container/page` + `@3xl/page:` when nested). Real-browser check: `e2e/helpers/layoutProblems.ts::textLayoutProblems`.
- **Sentry, errors only (#769):** `lib/observability/sentry.ts::sentryOptions` is shared by `instrumentation-client.ts` (`NEXT_PUBLIC_SENTRY_DSN`, inlined at build — a new DSN needs a rebuild) and `instrumentation.ts` (`SENTRY_DSN`). No DSN = no SDK. Every event passes `scrubSentryEvent`: query-less request URL, no `contexts.nextjs.request_path`, no `user`, no console breadcrumbs, URL breadcrumbs stripped; a new field that can carry a URL/header is scrubbed there (`sentryServer.test.ts`). The `SUB_PROCESSORS` Sentry row states exactly what the scrubber lets through — change both together. `app/global-error.tsx` is the only boundary (Next 16 prop `retry`) and must not claim the error was recorded. A jest suite that inits the client SDK restores jest.setup's fetch mock.

### Backend (`apps/backend/`, FastAPI)
- Async FastAPI, MongoDB via Beanie, S3 for files, `BackgroundTasks` for AI/ML work.
- Canonical Beanie model registry: `app/models/registry.py` (app lifespan + `setup_database` fixture).

### MCP Server (`apps/mcp/`)
- Exposes `eda_summary_tool` over SSE via the `mcp` SDK's `MCPServer` (entry `main.py`). **Server and backend client move together (#620):** both pin `mcp>=2,<3`; a new major migrates both. Relock with `uv lock --upgrade[-package mcp] --exclude-newer <a week ago>`, then plain `uv lock`.
- **The backend client speaks real MCP (#506):** `app/services/mcp_integration.py` uses `sse_client` + `ClientSession` with a bearer token, calls `eda_summary_tool` with `params={dataset_id, user_id}` (the server reads S3 and checks ownership). Bound both `timeout` and `sse_read_timeout` by `MCP_TIMEOUT`. Failures fall back, never fabricate. Read result fields as attributes (`result.is_error`, `result.structured_content`), never `getattr` with a default; raise a tool error after the session closes. Unit tests build the SDK's real `CallToolResult`.
- **`apps/backend` is NOT a package (no `__init__.py`):** with one, `apps/mcp` (named `mcp`) shadows the installed SDK under pytest. The `backend-integration` job runs `uv sync --frozen` in `apps/mcp` so the SSE round trip runs (`require_service`; `test_mcp_round_trip_runs_in_ci.py` bans a plain `pytest.skip`).

## Backend Conventions & Recurring Gotchas

### Routes, auth, errors
- **Routers mount only in `app/main.py` (#471, #530).** `test_every_router_is_mounted.py` fails on an unmounted route module or an `include_router` elsewhere. Review a newly mounted, never-reachable feature as new code (authz, metering, error paths).
- **Every handler carries its own auth dependency (#450, #914):** routers have no router-level deps. `test_every_route_requires_auth.py` fails on a route reaching none of `get_current_user_id`, `verify_api_key`, `require_admin`, unless it is in `_PUBLIC_ON_PURPOSE` (`module.function` + reason; stale entries fail), and on any non-FastAPI route outside its walk. Exception: admin routers (`admin.py`) guard at router level with `require_admin`, the stronger form.
- **Health (#503):** a health endpoint belongs in `health.py` only if it is a readiness dependency. `/health/ready` is Mongo-only with no outbound call (200/503 is the Docker healthcheck contract); upstream checks live at authenticated, rate-limited `GET /api/v1/health/dependencies` (on `liveness_router`). Health I/O is non-blocking (`asyncio.to_thread`).
- **Foreign ids answer 404 (#751, #985):** `BaseService.check_ownership` raises `NotFoundError`; datasets use `datasets.py::_callers_dataset`. A 403 is right only where the caller may already know the object exists (shared/public feature edits, API-key model scope); `test_no_403_existence_oracle.py` allow-lists those.
- **A recipe's `user_id` goes to its owner only (#914):** every handler that can return another account's recipe builds via `_recipe_response(recipe, viewer_id)`; copies never carry the source owner (a `TransformationRecipe.metadata` validator drops `original_owner`). Before putting anything about another account in a document its reader owns, check every surface that returns it whole.
- **Error handling (#269, #637, #518, #687):** `app/middleware/error_handlers.py` sanitises all 5xx (generic body + `X-Request-ID`); never `str(e)` in a 5xx. A 200 `{success: false}` body uses `internal_error_message("<What>")` + `logger.exception`; only domain errors with a user-facing `.message` (`ValidationError`, `OperationError`) pass through (`test_error_bodies_are_sanitized.py`). Job errors (`TrainingJob.error`, `BatchJob.error_message`) store `app/utils/job_failures.py::user_safe_failure_reason(exc)` — add new known modes to its classifier. Exception: batch per-row errors keep exception text because that path is in-memory only (`test_batch_row_errors_are_inference_only.py`; if it gains I/O, classify instead).
- **`UserData.id` is an ObjectId (#465):** coerce request ids with `app/utils/object_id.py::require_object_id`; only `Document.get(str)` coerces. A handler wrapping its lookup in `try/except Exception` must `except HTTPException: raise` first. Lookup tests seed real documents.
- **Route order:** register `/ml/{model_id}/<sub>` routes **before** the catch-all `/{model_id}`.
- **Published API description (#512):** `GET /api/v1/docs/openapi.json|yaml` = `published_spec(app)` (`app/services/api_documentation.py`): the live route table + description, licence, contact; no `servers` entry; nothing hand-stated that the app can state (auth per operation, limits from `settings`/`PLAN_LIMITS`). The SDK is per-model (`sdk_generator.py`, `/ml/{id}/sdk`) and its sample uses raw `required_input_features` (`_sdk_inputs`), never `MLModel.feature_names`. Guard: `test_generated_sdk_runs_against_a_live_server.py` (a real server trains in the background — wait for the model).
- **Customer-facing URLs come from `PUBLIC_API_URL` (#915, #942):** via `app.config.public_api_url()` / `model_training._public_api_base(request)`; the request base is the local-dev fallback only. Never `--forwarded-allow-ips` (uvicorn would trust `X-Forwarded-For`). `RelativeRedirectMiddleware` makes same-origin redirects relative.
- **A/B testing is removed (#502):** `test_ab_testing_is_removed.py` fails on any `/ab-testing` route. `ABTest`/`ABTestingService` remain (swept by erasure); reviving means wiring the serving path first.

### Models and schemas
- **Two model surfaces:** `MLModel` (`/api/v1/ml/`) is the real trained-model surface — build here. `ModelConfig` (`/api/v1/models/`) is dead legacy (train/deploy/performance are `410 Gone`). Bot plans routinely target the wrong one.
- **Schema ↔ type mirrors:** backend Pydantic schemas mirror frontend TS types — change both (e.g. `app/schemas/evaluation.py` ↔ `lib/types/evaluation.ts`).
- **New optional fields degrade:** add `MLModel`/schema fields optional/defaulted so old models validate (`partial=true`, not 500). Any new optional `MLModel` field must also be set on the `sample_ml_model` MagicMock fixture or `response_model=MLModel` validation breaks.
- **Index option changes need a new index name (#565):** Mongo refuses to rebuild an existing name with new options, failing startup. Declare a named `IndexModel`, drop the legacy index by script, run duplicate checks before deploy.
- **Beanie `Link` fields persist as DBRefs (#543):** query `{"link_field.$id": PydanticObjectId(...)}`, never the bare id.
- **Beanie `save()`** surfaces a unique-index violation as `RevisionIdWasChanged`, not `DuplicateKeyError`.
- **Concurrent writers write only their own fields (#983):** never `save()` a document read before an `await` — use `document.set({...})` (`test_dataset_writers_keep_each_others_fields.py`). Exception: `PUT /user_data/{id}` (no await between read and write; relies on `validate_on_save`).
- **datetime:** `datetime.now(UTC)` / `app/utils/datetime.py` (`utcnow`, `as_utc`). Mongo reads datetimes back naive — `as_utc` before comparing with aware values.
- **Removable dependency groups:** `interpretability` (shap/numba), `tuning` (optuna), `export` (ONNX) are PEP 735 groups in `default-groups`, lazy-imported; slim image: `uv sync --frozen --no-dev --no-group <group>`.

### AI services
- OpenAI (JSON mode) behind the shared circuit breaker + a deterministic rule-based fallback; endpoints must work **without** an API key.
- **Every client is built via `app/utils/openai_client.py` (#501)** (`build_openai_client`/`build_async_openai_client`): request `timeout` (`OPENAI_REQUEST_TIMEOUT`, clamped below worker timeout × breaker attempts) and `max_retries=0` (the breaker is the only retry layer). `test_openai_client_registry.py` bans raw construction. Never call the sync client inline in async code — `asyncio.to_thread` or the async client.
- **Every `chat.completions.create` lives inside an `openai*` breaker** (`test_ai_ceiling.py::TestEveryModelCallIsBehindTheCeiling`). The Next.js `/api/chat` proxy forwards to `POST /ai/chat`; the frontend has no `openai` dependency.
- **Summaries (#409, #981, #490, #679, #718):** processing stores explicit nulls, so `dataset_summarization.py` reads via `_stored(source, key, default)`, never `dict.get(key, default)`. A failed summary (`model_used == "error"`) carries `internal_error_message`; `/ai/summarize` returns it but does not store it (`test_ai_summarize_real_document.py`). On the secure upload paths the summary is built from `_summary_frame(df, pii_detections)` through `generate_ai_summary_safe(user_data_id, df)` — every flagged column redacted to numbered tokens — never the stored-schema `generate_dataset_summary` (allowed only for a clean `/upload/secure` dataset). `PIIDetector.mask_pii` is the *storage* mask (keeps partial values); never route third-party data through it.
- **PII risk (#608):** `PIIDetector` keeps the stronger of name and value signals; a name alone is medium, matching values make high (strictly > `HIGH_RISK_CONFIDENCE` 0.8), which sends `/upload/secure` to the `/confirm-pii-upload` gate.

### Datasets and S3
- **Two dataset id-spaces:** `DatasetMetadata` (string `dataset_id`, string-keyed children) and legacy `UserData` (ObjectId, `Link` DBRef children), dual-written and linked only by `(user_id, s3_url)`.
- **Every move to a new file goes through `app/services/dataset_link.py::record_new_file(doc, new_url)` (#467, #525, #723, #781, #960, #964).** It:
  - moves both twins (`file_path`, `s3_url`; the first move keeps the upload in `source_s3_url`) with one targeted `$set` each, never `save()`. It owns the link fields + `_SHAPE_FIELDS` (`num_rows`, `num_columns`, `columns`, `file_type`, `data_schema`); another field set before the move must be added there or is lost;
  - writes `file_type` from the new extension and `file_size` from one S3 HEAD;
  - appends the old URL to `superseded_s3_urls`, keeping the invariant that the current file is never in that list (undo/redo revisit URLs);
  - clears what was computed from the old file (`_forget_what_was_computed`: Redis `viz:{id}:*`, `VisualizationCache`, column stats). A new derived cache is cleared there or carries the file URL in its key; the chart cache does both (`source_url` on the row, a digest in the Redis key, `get_cached_visualization(…, source_url)`; rows without `source_url` are misses).
  Undo/redo/jump call it too, after setting the restored version's shape on the dataset. Inventory scripts: `inventory_dataset_links.py`, `inventory_orphaned_s3_objects.py`, `reconcile_model_artifacts.py`.
- **S3 keys are server-derived (#464, #581, #615):** `datasets/{user_id}/[masked_]{uuid}.{ext}`, built only by `dataset_s3_key` (`app/utils/s3.py`); the client filename never reaches a key. No reader admits pre-#581 bucket-root keys — don't reintroduce `allow_legacy_root`; only `scripts/reconcile_unprefixed_s3_keys.py` touches root objects.
- **One bucket resolver (#567, #621, #622, #507):** `app.config.resolve_configured_bucket()` is the only precedence; `utils.s3.configured_bucket()`/`allowed_bucket()` delegate and services read per call. No call site reads the bucket env vars (`test_s3_write_contract.py`). Every `S3Service` write runs `validate_object_key()` (namespace `datasets|transformed|models|batch-jobs|exports/{tenant}/…`) — hygiene, not authorization; pass ownership-checked keys.
- **Boot check (#495, #529):** in production-like envs the lifespan runs `s3_service.verify_bucket_writable()` (fails on no bucket, mock creds, or a failed write probe). The probe deletes the *version* it wrote (`_remove_probe`) because a plain delete on a versioned bucket leaves a noncurrent version + marker; any scratch write does the same.
- **boto3 clients (#519, #722):** only via `create_s3_client()` (bounded `Config`: connect 5s, read 20s, 3 standard retries, pool 20). `get_s3_client()` reuses one client keyed on credentials/endpoint/region, returns `None` without env; `reset_s3_client()` clears it. Tests stub `app.services.s3_service.get_s3_client` (point of use) or `app.utils.s3.create_s3_client`; `tests/conftest.py` clears the cache per test; a test that sets credentials also points `AWS_ENDPOINT_URL` at a dead local address.
- **One download core (#531, #170, #466):** reads go through `app/utils/s3.py` (`resolve_validated_object` → `allowed_bucket` → `validate_object_key`; `check_object_size`): one `get_file_from_s3`, one `download_file_from_s3`, plus key-only `S3Service.download_file_bytes`. No raw `get_object`/`download_file*` elsewhere (`test_s3_download_registry.py`). `file_path` is a raw key after upload and a URL after a transformation — never branch on its shape; use `downloadable_url(file_path, s3_url)`. Only LocalStack tests see this class (`test_transformation_first_apply_localstack.py`). Charts read only the columns they need (`read_columns_from_bytes`, `visualizations._chart`).
- **Reading a stored dataset (#524, #733, #858, #888, #940, #1019):** always `s3_service.read_dataframe_from_bytes` or `load_dataframe_from_s3`, never bare `pd.read_csv`. A declared type is checked against magic bytes (`PAR1` head and footer) and raises `FormatMismatchError`; `file_type=None` dispatches on the bytes (`_kind_of`). An object's name must say what it holds (versions: `…/versions/{version_id}/data.parquet`).
- **`file_type` (#902, #937):** an Excel type is its extension (`xls`/`xlsx`), normalised on `UserData`/`DatasetMetadata` by `excel_under_its_extension` (also on read) — never add `"excel"` to a reader; only `DataProcessor` uses it internally via `_reader_type`. `/confirm-pii-upload` stores `csv` for a masked copy (key ends `.csv`); `dataset_link._file_type_of` treats any `masked_` object as csv. A writer that changes the bytes' format changes the stored type and key extension together. Audit legacy rows with `scripts/audit_dataset_file_types.py` (raw documents, targeted `$set`).
- **Filenames (#585, #648):** `UserData`/`DatasetMetadata` run `sanitize_filename` (basename, no control chars or leading dots, ≤255, non-empty) with `validate_on_save = True`. Every download header uses `app/utils/filenames.py::attachment_disposition` (`test_no_download_header_is_built_by_hand`).
- **Failed requests delete unowned uploads (#735, #898, #899):** `upload_file_to_s3` records keys per request (`_recorded`); `UnownedUploadCleanupMiddleware` (`app/middleware/upload_cleanup.py`) deletes, on 4xx/5xx/exception, objects no document owns. Ownership is **looked up**, scoped to the tenant in the key's second segment: `UserData`/`DatasetMetadata` `s3_url`/`file_path`/`source_s3_url`/`superseded_s3_urls`, `TransformationConfig.current_file_path`, `BulkTransformationJob.output_file_path` (raw or percent-encoded). A new location field joins `_OWNERS`; writers key objects `{namespace}/{user_id}/…`. Lookup/delete failures leave the object. A route answering `success: false` in a 200 adds `@discards_uploads_on_reported_failure` under `@router`. Bulk jobs record their own uploads (`record_request_uploads()`) and discard before marking failed. Tests patching `upload_file_to_s3` wrap the stand-in with `app.utils.s3._recorded` or use LocalStack.
- **Chunked upload (#454, #462–#464, #526, #580, #584):** init takes `Form(...)`; session ids come from `secrets.token_urlsafe` (`[A-Za-z0-9_-]` guard — they are spliced into filenames). - **History is one `TransformationConfig` per dataset (#800):** resolve via `TransformationService.get_dataset_config(dataset_id, user_id)` (owner-scoped), never `get_transformation_config` (config-id space).
- **Either id space is accepted (#850, #847):** resolve via `dataset_link.ensure_metadata_twin(dataset_id, user_id)` (reuses or creates the twin for CSV/Excel/JSON/Parquet, refuses other types), never `DatasetMetadata.find_one({"dataset_id": …})`. - **`apply_pipeline` is the one apply path (#1060):** all or nothing. - **Orchestrators (#842):** `train_model_task` and `AutoMLEngine.run` delegate to named steps — in `model_training.py`: `_build_engine`, `_JobReporter`, `_run_training`/`_fit_within`, `_store_trained_model`, `_record_completion|failed|cancelled`; in the engine: `_prepare_data`, `_tuning_results`, `_train_candidates`/`_train_one`, `_deploy_best`. - **Training config is bounded per tier (#500):** typed request models with `extra="forbid"`; a new knob goes in the request model and in `TrainingCeilings` (`app/billing/plans.py`). Over a ceiling → 422 naming knob/value/limit, never clamped. Estimator hyperparameters are not caller-reachable. The tier's wall clock is `asyncio.wait_for` (the engine's `time_limit` is soft). - **Training concurrency (#498, #665, #901):** `app/services/training_admission.py` — a per-tenant cap → 429 (after the quota reservation, so it refunds), and a per-loop `Semaphore(MAX_CONCURRENT_TRAINING_JOBS)` around the load (parsed in `asyncio.to_thread`) and `engine.run`. The slot wait runs the heartbeat pump (`_training_slot`). Never raw `n_jobs=-1`: `bounded_n_jobs` / `TRAINING_MAX_N_JOBS`. Caps read via `_env_positive_int`.
- **The training task records nothing for a job someone else ended (#901, #936):** `_require_in_flight` runs on taking the slot and after the fit (`TrainingNoLongerInFlight`). Whole-document job writes go through `_refreshed_job` + `_record` (Beanie `replace()`, which raises on a missing row; `save()` would re-insert an erased job); all other task writes are partial `$set`/`$push`.
- **Feature engineering, fit and serving (#697, #806, #838, #840, #906, #909, #911):**
  - Encodings are gated on their key (`"encoder"` one-hot, `"label_encoders"` label). Values are keyed by `_label_keys`; one-hot is matched on `_match_keys` and built by `_one_hot`, never the encoder's `transform`. Category options go through `_label_keys`. Serving tests send strings, as the form does.

- **Model report states only recorded facts (#795, #801):** each section has a `Provenance`; unrecorded → "not recorded". - **Model export (#468, #632):** `ModelStorageService.load_model(model_id, user_id)` is tenant-scoped and returns `(model, feature_engineer)`; only `ModelExportService._load_owned` calls it, after `_owned()` 404s a foreign model (before the converter check). `NotFoundError`→404, `ExportFormatUnavailable`→501, other `ValueError`→400. - **Model cache (#265, #489, #725):** `_ModelArtifactCache` is a TTL-LRU keyed `(model_id, user_id)` (never `model_id` alone); inference goes through `run_locked_inference`. ### Billing and limits
- **Plan enforcement (#368):** `app/billing/enforcement.py`. `quota(<metric>)` atomically reserves via `metering.consume()` (a conditional `$inc` + upsert; the `DuplicateKeyError` is the denial) → **402** with limit/used/resets_at/upgrade_available. Enforcement is the only counter — a guarded route never also calls `metering.record()`. `QuotaRefundMiddleware` refunds on ≥400 against the reserved period; a 2xx that did no work calls `enforcement.release(request)`. Reservations on one request accumulate. JSON predict routes use `per_record=True`. Enforcement fails closed; `record()` fails open. Tests hitting a metered route need `setup_database`. `/billing/status` derives `limits` from `METERED_METRICS`.
- **Batch metering (#460, #486):** count CSV rows (stdlib `csv`, `MAX_CSV_FIELD_BYTES` 1 MiB; a failure raises `CsvCountError` → 400, never `return 0`) and reserve **before** creating the job. A retry reserves `progress.total_records`; `retry_job` claims with one conditional `find_one_and_update`.
- **Metering dataset creation (#459, #609):** `quota("uploads")` on every route that creates a dataset (`/upload/secure`, `/confirm-pii-upload`, chunked `complete`, `/upload/`, `/datasets/upload`, onboarding sample load; feature apply reserves inside the handler only when `create_new_dataset`). Registry: `test_dataset_routes_are_metered.py` (live route walk + AST reach to `UserData`/`DatasetMetadata` construction; routes reaching only `ensure_metadata_twin` go in `_EXEMPT_BY_REACH`). `app.routes` is not flat on FastAPI 0.139 — routers are lazy `_IncludedRouter` wrappers.
- **Storage ceiling (#768, #781):** `app/billing/storage.py::enforce_storage_ceiling(user, incoming_bytes)` runs before the S3 put in every `_MUST_BE_METERED` dataset route and chunked `init`; it sums `UserData.file_size`, `DatasetVersion.file_size`, `MLModel.model_size` and answers a `quota_exceeded` 402 as `storage_mb`. A new dataset writer sets `file_size` and calls the check.
- **AI metering (#461, #683, #728, #768):** `ai_calls` is finite on every tier (`_env_positive_int`; a `-1` override falls back). Every route that can reach a model carries `quota("ai_calls")` (`test_ai_routes_are_metered.py`) and releases when no model ran (`generated_by`, `metadata["ai_used"]`, `metadata.fallback_mode`) — set such a flag only after the call returns. A global daily ceiling (`app/billing/ai_ceiling.py`, `AI_CALLS_DAILY_CEILING`, default 500, tenant `__global__`) is enforced in `with_circuit_breaker` for every `openai*` breaker, outside the retry; past it `AICeilingReached` → fallback (`/ai/chat` → refunded 503). Unit tests driving a mocked OpenAI client need the `ai_ceiling_open` fixture. Feature-suggestion lookups (explain/apply/feedback) read the cache only and carry no quota.
- **Entitlement (#366, #458, #509, #510, #598):** `Subscription.is_entitled` is the single predicate; callers read `effective_tier`. It needs an entitled status **and** an unlapsed period: `PAST_DUE` is entitled (`DUNNING_GRACE` 30d), `unpaid` is not — never merge them; ACTIVE grace is `ENTITLEMENT_GRACE` 3d; a missing `current_period_end` falls back to `updated_at` + grace. `_period_end()` reads top-level, then the item (pinned `STRIPE_API_VERSION`, `test_stripe_api_version.py`) and never clears a known value. The webhook persists via one conditional upsert (`last_event_at <= event.created`), retrying once on a first `DuplicateKeyError`; only fields present are `$set`. A settled `checkout.session.completed` alone entitles (reads the subscription from Stripe; 503 on failure). Each event has a handler in `_HANDLERS`; `.env.staging.example` lists every `HANDLED_EVENTS` entry (`test_staging_example_lists_every_webhook_event`). Stripe calls: 10s timeout, 1 retry. Repair: `scripts/reconcile_subscriptions.py` (tier and status; conditional on `updated_at`).
- **Refund window (#602):** `first_paid_at` is stamped once, on the first genuinely paid checkout (`paid` or `async_payment_succeeded`; never `no_payment_required`). `app/billing/refunds.py` is the eligibility source; `test_refund_window.py` holds `REFUND_WINDOW_DAYS` equal to `refundWindowDays` in `company.ts`.
- **Rate limiting (#151, #455, #483, #588):** global `RateLimitMiddleware` on `/api/v1`; per-key buckets on `/production/v1/models`. Anonymous key: socket peer, or `X-Real-IP` with `RATE_LIMIT_TRUST_PROXY` (nginx overwrites it; `test_nginx_real_ip.py`). **Never read `X-Forwarded-For`.** Disabled in tests — build with `enabled=True` to test it. `limit <= 0` means no enforcement, so: `CreateAPIKeyRequest.rate_limit` is `ge=1`; `app/billing/api_keys.py` clamps to `api_key_rate_limit_ceiling(tier)`; `reconcile_user_api_keys` (run from the webhook) sets `min(requested_rate_limit, ceiling)` in both directions; the middleware floors at 1. Rate ceilings in `plans.py` stay finite (`UNLIMITED` means the opposite here). `api_key_rate_limit` is not in `METERED_METRICS`.
- **A best-effort security control that fails is an ERROR and a counter (#590):** a failed re-clamp (`reconcile_user_api_keys`, which never raises into the webhook) logs at ERROR naming `scripts/fix_api_key_rate_limits.py --apply`; a limiter that fails open (the middleware's `_hit`, and `RedisRateLimitStore.hit` itself, which catches a Redis outage before the middleware sees it) logs one ERROR per outage. Both count in `security_control_failures_total{control}` and log the exception class only (ERROR logs reach Sentry). A new best-effort path on a security control does the same, never a bare `logger.warning`. Guard: `test_failed_security_controls_alert.py`. The alert itself waits on log aggregation (#785).

### Jobs
- **Batch prediction (#485, #487, #515, #653, #904, #1032):**
  - Per-loop `Semaphore(MAX_CONCURRENT_BATCH_JOBS)`; per-tenant cap `MAX_CONCURRENT_BATCH_JOBS_PER_USER` → 429, checked before the S3 upload and held exactly by `admission_slot` + the unique partial index `user_live_slot_unique` (PENDING/RUNNING only; needs MongoDB ≥6; slot stored as a 32-bit int). `_discard_unadmitted` undoes a failed create.
  - Every status write is conditional (`_claim_running`, `_persist_progress`, `_finalize_if_running`, atomic `cancel_job`); the loop re-checks cancellation between chunks. The create route writes `input_size_bytes` with a one-field `set`, never `job.save()`.
  - A run is bounded by `BATCH_JOB_WALL_CLOCK_SECONDS` (`asyncio.wait`, not `wait_for`). Queued jobs pump heartbeats (`heartbeat_pump`).
  - The unprocessed remainder is refunded once, by whoever claims `remainder_refunded`. Any write that settles a job `$push`es onto `refunds_owed` (`app/billing/owed_refunds.py::owed`) in the same write; `settle` pays idempotently (`metering.refund(..., refund_id=…)`) and `$pull`s; the reaper pays leftovers (`settle_pending`). A new refund path follows this. Refunds go against `job_reaper.reservation_period`.
  - Keys: `batch-jobs/{user_id}/{model_id}/{job_id}/{input.csv|results.ext}`.
- **Bulk transformation jobs (#925)** use the same conditional writes (`_claim_running`, `_write_if_running`, conditional `cancel_job`).
- **Stale jobs are reaped (#484):** `app/services/job_reaper.py::reap_stale_jobs` fails in-flight jobs whose `last_heartbeat` is older than `STALE_JOB_TIMEOUT_SECONDS` and refunds against the reserved period, via atomic `find_one_and_update` claims (safe across workers). Partial training writes include `last_heartbeat`; `retry_job` refreshes it.
- **Prediction log (#488):** the `PredictionEvent` collection, TTL-indexed (`PREDICTION_EVENT_TTL_SECONDS`); batches log via one `insert_many`; erased with its model.
- **Funnel telemetry (#769):** server-written `ProductEvent` rows via `app/services/product_events.py::record(user_id, event, once=…)` (never raises; `once` dedupes through a unique partial index). `account_created` comes from NextAuth `events.createUser` (`lib/product-events.ts`; shape is a contract with `app/models/product_event.py`). 13-month TTL; a new event type needs privacy-policy disclosure. Readout: `GET /api/v1/admin/funnel`.

## Automated Workflow Configuration
- **Quality gates before PR:** tests pass, coverage >85%, ruff/eslint clean, mypy/tsc clean, no TODO/FIXME/NotImplemented markers, OWASP scan, and `scripts/quality/crap.sh` passes: every added or modified function scores CRAP < 6 — split or cover it, never skip (exit 2 = a measurement is missing: follow the hint; backend coverage needs MongoDB). No standing exemptions.
- **CRAP gate reads `.tsx` with lizard's TypeScript reader, which misreads some shapes (#765, #808, #825, #855).** Write instead:
  - `props: {…}` destructured in the first statement (`const { a } = props`), not a typed destructured parameter.
  - callbacks typed `VoidFunction` or as a method signature (`onSelect(view: View): void`), not `() => void` in a props type.
  - `{x ? <A/> : <B/>}`, not a parenthesised JSX ternary.
  - a named type, not an inline object type as a generic argument (`ComponentType<{…}>` blinds the whole file).
  - `unknown` + a cast at the caller, not a generic function declaration.
  - a component with a statement before `return <JSX>` (a bare return gets no LCOV line); inline JSX arrows named in the component body; `??` counts as two branches; a file not yet `git add`ed reads as absent.
  When line ranges look wrong, run `uvx lizard -l typescript <file>`.
- **CodeRabbit:** max 3 iterations; auto-fix style/types/simple bugs/docs. Escalate on iteration-3 failures, architecture changes, or security decisions.

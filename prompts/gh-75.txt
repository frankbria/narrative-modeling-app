## Observations

The codebase already has a solid foundation for AutoML with `file:apps/backend/app/services/model_training/automl_engine.py`, `file:apps/backend/app/services/model_training/problem_detector.py`, and `file:apps/backend/app/services/model_training/feature_engineer.py` implementing core ML functionality. The infrastructure includes S3 storage via `file:apps/backend/app/services/model_storage.py`, MongoDB models in `file:apps/backend/app/models/ml_model.py`, Redis caching in `file:apps/backend/app/services/redis_cache.py`, and a batch job system in `file:apps/backend/app/models/batch_job.py`. Frontend components like `file:apps/frontend/components/ModelTrainingButton.tsx` exist but lack the comprehensive training interface required. Missing components include AI-guided algorithm selection, parallel training, WebSocket progress tracking, class balancing, time series algorithms (ARIMA/Prophet), and the dedicated training page UI.

## Approach

The implementation will enhance the existing AutoML engine with AI-guided algorithm selection using OpenAI API for explanations, implement parallel training using Python's `asyncio` and `concurrent.futures`, add WebSocket support for real-time progress updates, integrate class balancing with `imbalanced-learn`, and add time series support with `statsmodels` and `prophet`. The frontend will be built as a new page at `file:apps/frontend/app/datasets/[id]/train/page.tsx` with components for algorithm selection, training progress, and model comparison. The approach leverages existing infrastructure (Redis for progress state, S3 for models, MongoDB for metadata) while adding new capabilities incrementally. Training modes (quick/comprehensive) will control the number of algorithms and hyperparameter search depth.

## Implementation Steps

### Phase 1: Backend - Enhanced AutoML Engine

#### 1.1 Algorithm Recommendation System

Create `file:apps/backend/app/services/model_training/algorithm_selector.py`:
- Implement `AlgorithmSelector` class with method `select_algorithms(problem_type, data_profile, config)` returning ranked algorithm recommendations
- Define `DataProfile` dataclass capturing dataset size, feature types distribution, class balance ratio, missing value percentage, and cardinality metrics
- Define `AlgorithmRecommendation` schema with fields: algorithm name, priority (1-10), expected_performance, training_time_estimate, interpretability_score, explanation, and pros/cons lists
- Implement selection logic based on rules:
  - Dataset size: Use SVM/KNN only for <5000 samples, LightGBM/XGBoost for large datasets
  - Class imbalance: Prioritize tree-based models, recommend class balancing
  - High cardinality: Prefer tree-based over linear models
  - Interpretability needs: Prioritize Logistic/Linear Regression, Decision Trees
  - Speed requirements: Prioritize LightGBM, Linear models
- Integrate with OpenAI API to generate natural language explanations for each recommendation using `file:apps/backend/app/services/openai_service.py` pattern

#### 1.2 AI Explanation Service

Create `file:apps/backend/app/services/model_training/explanation_service.py`:
- Implement `ExplanationService` class using OpenAI API
- Method `explain_algorithm_selection(algorithms, data_profile, problem_type)` generating why each algorithm was selected
- Method `explain_best_model(best_model, all_models, comparison_metrics)` explaining why the best model was chosen
- Method `explain_model_tradeoffs(model_a, model_b)` comparing two models with trade-off analysis
- Use structured prompts with data characteristics, algorithm properties, and performance metrics
- Cache explanations in Redis using `file:apps/backend/app/services/redis_cache.py` with key pattern `explanation:{hash}`

#### 1.3 Parallel Training Infrastructure

Enhance `file:apps/backend/app/services/model_training/automl_engine.py`:
- Add `ParallelTrainingConfig` with fields: max_parallel_jobs, use_multiprocessing, timeout_per_model
- Implement `_train_models_parallel()` method using `asyncio.gather()` with `concurrent.futures.ProcessPoolExecutor` for CPU-bound training
- Create `_train_single_model_async()` wrapper that runs sklearn training in executor
- Add progress callback mechanism: `on_model_started`, `on_model_completed`, `on_model_failed`
- Implement timeout handling using `asyncio.wait_for()` with graceful degradation
- Store intermediate results in Redis with key pattern `training:{job_id}:model:{algorithm}`

#### 1.4 Class Balancing Support

Enhance `file:apps/backend/app/services/model_training/feature_engineer.py`:
- Add dependency `imbalanced-learn` to `file:apps/backend/pyproject.toml`
- Add `ClassBalancingConfig` with fields: method (smote/random_oversample/random_undersample/smote_tomek), sampling_strategy, k_neighbors
- Implement `_balance_classes()` method in `FeatureEngineer`:
  - Detect class imbalance (ratio > 2:1)
  - Apply SMOTE for minority oversampling using `imblearn.over_sampling.SMOTE`
  - Apply RandomUnderSampler for majority undersampling using `imblearn.under_sampling.RandomUnderSampler`
  - Apply SMOTE+Tomek for combined approach using `imblearn.combine.SMOTETomek`
- Add to `fit_transform()` method before feature selection
- Store balancing metadata in `FeatureEngineeringResult.metadata`

#### 1.5 Time Series Algorithm Support

Create `file:apps/backend/app/services/model_training/time_series_models.py`:
- Add dependencies to `file:apps/backend/pyproject.toml`: `statsmodels>=0.14.0`, `prophet>=1.1.0`
- Implement `ARIMAModel` wrapper class with auto-ARIMA using `pmdarima.auto_arima`
- Implement `ProphetModel` wrapper class with automatic seasonality detection
- Implement `TimeSeriesPreprocessor` for datetime feature extraction, lag features, rolling statistics
- Add time series specific cross-validation using `sklearn.model_selection.TimeSeriesSplit`
- Integrate into `AutoMLEngine._get_candidate_models()` when `problem_type` is TIME_SERIES_*

#### 1.6 Training Modes Implementation

Enhance `file:apps/backend/app/services/model_training/automl_engine.py`:
- Add `TrainingMode` enum: QUICK, BALANCED, COMPREHENSIVE
- Implement mode configurations:
  - QUICK: 3-5 algorithms, no hyperparameter tuning, 3-fold CV, 10min timeout
  - BALANCED: 5-7 algorithms, basic grid search, 5-fold CV, 30min timeout
  - COMPREHENSIVE: 8-10 algorithms, extensive grid search, 10-fold CV, 2hr timeout
- Add `optimize_for` parameter: ACCURACY, SPEED, INTERPRETABILITY affecting algorithm prioritization
- Implement basic hyperparameter tuning using `sklearn.model_selection.GridSearchCV` for COMPREHENSIVE mode

#### 1.7 Enhanced Model Comparison

Enhance `file:apps/backend/app/services/model_training/automl_engine.py`:
- Implement `ModelComparison` dataclass with fields: ranking, metric_comparison_table, performance_summary, recommendation, explanation
- Implement `compare_models()` method:
  - Rank models by primary metric (accuracy/R²/F1)
  - Calculate secondary metrics: training_time, model_size, interpretability_score
  - Generate comparison matrix with all metrics
  - Identify best model considering trade-offs
  - Use `ExplanationService` to generate natural language comparison
- Add statistical significance testing using paired t-test on CV scores

## Architecture Diagram

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant AutoML
    participant AlgoSelector
    participant OpenAI
    participant Redis
    participant WebSocket
    participant S3
    participant MongoDB

    User->>Frontend: Navigate to /datasets/{id}/train
    Frontend->>API: GET /datasets/{id}
    API-->>Frontend: Dataset metadata
    
    User->>Frontend: Select target column
    Frontend->>API: POST /detect-problem-type
    API->>AutoML: ProblemDetector.detect()
    AutoML-->>API: ProblemType + confidence
    API-->>Frontend: Detection result
    
    User->>Frontend: Configure training
    Frontend->>API: POST /recommend-algorithms
    API->>AlgoSelector: select_algorithms()
    AlgoSelector->>OpenAI: Generate explanations
    OpenAI-->>AlgoSelector: AI explanations
    AlgoSelector-->>API: Algorithm recommendations
    API-->>Frontend: Recommended algorithms
    
    User->>Frontend: Start training
    Frontend->>API: POST /train-automl
    API->>MongoDB: Create TrainingJob
    API->>Redis: Initialize progress
    API-->>Frontend: job_id
    
    Frontend->>WebSocket: Connect /ws/training/{job_id}
    
    API->>AutoML: run_automl() async
    
    loop For each algorithm
        AutoML->>AutoML: Train model (parallel)
        AutoML->>Redis: Update progress
        Redis->>WebSocket: Broadcast progress
        WebSocket-->>Frontend: Progress update
        Frontend->>User: Show progress
        AutoML->>S3: Save model
        AutoML->>MongoDB: Save model metadata
    end
    
    AutoML->>AlgoSelector: compare_models()
    AlgoSelector->>OpenAI: Generate comparison
    OpenAI-->>AlgoSelector: AI explanation
    AlgoSelector-->>AutoML: ModelComparison
    
    AutoML->>MongoDB: Update TrainingJob (completed)
    AutoML->>Redis: Final progress
    Redis->>WebSocket: Broadcast completion
    WebSocket-->>Frontend: Training complete
    
    Frontend->>API: GET /training-jobs/{job_id}/results
    API->>MongoDB: Fetch results
    API-->>Frontend: All models + comparison
    Frontend->>User: Show model comparison
```
